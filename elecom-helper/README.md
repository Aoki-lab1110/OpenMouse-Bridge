# v0.3.5: クリックで残るアプリ一覧

追加操作「アプリ切り替え（クリックで一覧表示）」はAppKit標準メニューで実行中の通常アプリを表示します。短く押しても一覧が残り、アプリ名のクリックまたは矢印＋Returnで切り替えます。Esc・外側クリックで閉じます。⌘などの合成キーを送りません。アプリ一覧を開くときだけ同梱の `openmouse-app-picker` を起動し、選択・キャンセルで終了します。重複起動を防ぎ、子プロセスを回収します。設定変更・入力確認開始・切断・終了でも閉じます。常時のアプリ監視・グローバルキー監視・通信・自動起動は追加しません。

現在の実機設定は6=Mission Control、7=アプリケーションのウインドウ、8=アプリ一覧です。v0.3.4のF11・長押し⌘Tab・解放後の物理キーボード⌘Tabはユーザーが動作確認しました。v0.3.5でユーザーが実物の6・7・8番を押し、3操作すべての動作、8番の短押し後の一覧保持、クリックでのアプリ切り替えを確認しました。既存の⌘Tab割り当ては長押し方式のまま保持します。

一覧用実行ファイルは `bundle-macos.sh` がAppleのSwiftコンパイラーで作成します。CLIで一覧を使う場合も、まず同スクリプトで.appを作成して起動します。通常のキー・ウインドウ操作はRustのCLI単体でも使えます。

# OpenMouse EX-G PRO for macOS (experimental)

EX-G PROの追加ボタン6〜8を、Command/Control/Option/Shiftと通常キーの組み合わせに割り当てる、独立した小さなヘルパーです。例：⌘Z、⌘C、⌘⇧Z。通常ボタン1〜5、移動、スクロールは変更しません。

v0.2.0では「Mission Control」「アプリケーションのウインドウ」「デスクトップを表示」を選べます。F11などの通常キー送信とは区別します。保存済みのv0.1.0のショートカット設定も読み込めます。旧版を起動中なら、先に専用画面の「常駐処理を終了」で閉じてから新版を開いてください。

v0.3.3では実物のボタンを押して番号を確認し、そのまま割り当てを編集できます。接続名・接続方式・メーカー定義の機種系列も表示します。サイズや色を含む正確な型番は共通のBluetooth名やPIDからは区別できないため、本体底面で確認します。

v0.3.4ではキー送信に独立したCGEventSourceを使い、合成した修飾キーの押下・解放を対にします。⌘Tab（⌘⇧Tabを含む）は実物のボタンを押している間だけ⌘を保持し、離すと確定します。切断・設定保存・入力確認開始・通常終了でも解除し、解放パケットが失われた場合は15秒で解除します。物理キーボードの修飾キーは解放しません。古いv0.3.3でキーが効かなくなった実機ではMac全体の再起動で復旧しました。原因の特定は完了していません。v0.3.4のF11・長押し⌘Tab・解放後のキーボード⌘Tabは実機確認済みです。旧版を再起動して検証しないでください。

**Mouse Assistant 6.4.0の機種定義に基づく実装です。Bluetooth実機のVID/PID一致と入力受信を確認しました。** 設定をマウスの本体へ書き込む方式ではなく、このMacでのソフトウェア変換です。通常版OpenMouse Bridgeを起動する必要はありません。

## 起動・設定・終了

1. ビルドした `OpenMouse EX-G PRO.app` を開くと、ブラウザに `http://127.0.0.1:17847` の専用画面が開きます。メニューバー、Dock、ログイン項目は追加しません。
2. 「macOSの許可設定を開く」から、入力監視とアクセシビリティにこのアプリを許可します。OSの許可変更後は「常駐処理を終了」で終了し、アプリを開き直します。必要ならシステム設定で `.app` を手動追加します。
3. 機種を選び、各追加ボタンのキーと修飾キーを選びます。ZとCommandで⌘Z。チェックを有効にして「保存して適用」を押します。初回は割り当て無効です。
   ウインドウ操作はドロップダウンの「macOSの操作」から選びます。Mission Controlは全体の一覧、アプリケーションのウインドウは現在のアプリの一覧、デスクトップを表示はウインドウを退ける操作です。この3操作では修飾キーを設定しません。
4. 「ボタン確認を開始」を押して実物のボタンを押します。通常ボタン1〜5を含む押下中の状態と押下回数が表示され、短いクリックも見逃しません。追加ボタン6〜8を押すとその設定欄を自動で開きます。画面の番号をクリックして切り替えることもできます。これは物理位置の名称ではなくHIDボタン番号です。確認中は割り当て操作を停止します。「ボタン確認を終了」で保存済みの割り当てに戻ります。確認画面からの更新が30秒止まると自動復帰します（ネイティブ側にタイマーは追加しません）。
5. ブラウザを閉じても変換は続きます。「常駐処理を終了」でヘルパー自体が終了します。再びアプリを開くと画面が開きます。自動起動はしません。

設定保存先：`~/Library/Application Support/OpenMouse/elecom.json`。接続方式を変えても同じ機種の割り当てを使います。再起動で有効設定を復元します。破損・不正な設定は起動時に拒否し、勝手にキーを送信しません。

## 処理と通信

- ネイティブヘルパー1プロセス。IOHIDの入力コールバックとローカルHTTPサーバーだけを常駐させます。既存Bridge本体の依存・起動処理を使用しない独立crateです。
- macOSの3操作は、Apple標準Mission Control.appと同じ `CoreDockSendNotification` を呼び出します。ApplicationServices内の非公開シンボルを動的に解決し、3個の固定通知名だけを使います。非公開APIなので将来のOS互換性は保証しません。シンボルがない場合は、そのMacの `com.apple.symbolichotkeys` をCFPreferencesで読み、CGEventのキー送信へフォールバックします（この経路の実動作は未確認）。OS設定変更、追加の子プロセス、シェル、AppleScript、自由なコマンド実行はありません。
- 対象Vendor/Product/PrimaryUsageだけを非排他的に開きます。マウス全体の占有、イベントタップ、キーボード監視、アプリ監視、HID設定書込みはありません。
- 通常ショートカットは追加ボタンの立ち上がりでキーのdown/upを1回送り、押しっぱなしのリピートはしません。⌘Tabだけはマウスの解放まで修飾キーを保持します。標準とvendorレポートはそれぞれ初期状態を確立するので、接続直後に既に押されているボタンは一度離すまで動作させません。最初のレポートが最初の押下で届く機種では、その最初の押下も送信せず、離して再押下が必要です。
- 入力イベント、利用アプリ、キー入力をファイルに記録しません。保存するのは割り当て設定だけです。画面にはボタン番号、押下状態、回数を表示します。
- 外向きの接続、テレメトリー、自動更新、ゲーム検出、バッテリー監視、Electron、LaunchAgentはありません。待受はIPv4 `127.0.0.1:17847` のみ。APIは正確なHost/Originを検証します。
- 専用UIはローカルJS/CSSとシステムフォントのみ。CSPで通信先を同一オリジンに制限します。通常版OpenMouse画面には既存の外部通信機能が残るため、無通信で使う場合は専用画面を使ってください。
- 画面を表示している間だけ、通常は2秒ごと、ボタン確認中は250msごとにローカルで状態を更新します。ブラウザを閉じると停止します。マウスの定期読み取りや権限確認のタイマーは使用しません。⌘Tabの保持時だけ、15秒の解放期限を単発で予約します。ボタン状態と8個の押下回数だけをメモリーに保持し、入力履歴やマウス移動量は保存・送信しません。
- UI終了、Ctrl+C、SIGTERMでHTTPとネイティブ入力監視を停止します。二重起動は同じポートの排他で防ぎます。

## 対象機種と未検証事項

| Vendor | Product | メーカー機種定義 | 接続 | Report ID |
| --- | --- | --- | --- | --- |
| 056e | 013d | M-XGx50MB | USB受信機 | 1 |
| 056e | 013e | M-XGx50MB | Bluetooth | 2 |
| 056e | 0128 | M-XPT1MR | 有線 | 1 |
| 056e | 0129 | M-XPT1MR | USB受信機 | 1 |
| 056e | 0130 | M-XPT1MR | Bluetooth | 1 |

マウスコレクションはUsage Page 1 / Usage 2に限定します。標準マウス入力はReport ID付き8byte、または別引数でIDを受ける7byte payloadだけを受理します。メーカー定義はIDの次の1byteを8ボタンのビットマスクとしており、追加ボタン6/7/8はbit5/6/7です。

Bluetooth実機056e:013eでは通常クリックとFn1/2/3の押下・解放を受信し、上記3種類のmacOS操作を実行できました。再接続、複数機種、全ショートカットの実行、通常クリックやスクロールへの影響は引き続き確認対象です。登録外IDや不一致パケットは無視します。ファームウェア初期設定や別モデルが同じ挙動であるとは保証しません。

この実装はOSの元の追加クリックを抑止しません。アプリがボタン6〜8にも独自の動作を持つ場合、ショートカットと重複する可能性があります。メーカーアプリと同時起動すると二重変換になる可能性があります。イベントタップによる抑止は現在の実装範囲に含めていません。チルト左右は今回の割り当て対象に含めていません。

## ソースからビルド

macOS、Node.js 22以上、Rust 1.88以上/Cargo、Appleのコマンドラインツールが必要です。GitHubの `feat/elecom-exg-pro` ブランチを取得します。

```sh
git clone -b feat/elecom-exg-pro https://github.com/Aoki-lab1110/openmouse.git app
git clone -b feat/elecom-exg-pro https://github.com/Aoki-lab1110/OpenMouse-Bridge.git bridge
cd app
npm ci --ignore-scripts --no-audit --no-fund
npm run build:elecom
cd ../bridge
sh elecom-helper/bundle-macos.sh ../app/dist-elecom
```

ビルド時の依存取得はネットワークを使用します。実行時は使用しません。アプリはローカルのad-hoc署名です。Developer ID署名・公証版ではありません。配布用に公証した成果物は作成していません。

CLIの場合：

```sh
cargo run --locked --release --manifest-path elecom-helper/Cargo.toml -- --ui-dir ../app/dist-elecom
```

`--config PATH` で設定先を変更できます。CLIではブラウザを自動で開きません。UIを開かなくても保存済みの割り当てを処理します。

`--safe-start` は保存済みの割り当てを読みながら、変換を無効にして起動します。設定ファイルを変更せず、UIから有効にして保存するまでキーを送りません。

## 検証とライセンス

```sh
cargo test --locked --manifest-path elecom-helper/Cargo.toml
cargo clippy --locked --manifest-path elecom-helper/Cargo.toml --all-targets -- -D warnings
```

テストは入力デコード、不正設定の拒否、ボタンの立ち上がり、通常ボタンの除外、Host/Origin検証を対象にします。UIの⌘Z/⌘⇧Z/⌘C設定と永続化、終了もローカルで確認しました。Bluetooth実機で追加ボタン6=アプリケーションのウインドウ、7=Mission Control、8=デスクトップ表示をユーザーが押し、3個とも動作することを確認しました。通常キーの全組み合わせは実動作未確認です。

テストには、保存済みキーボード設定の互換性、3種類のmacOS操作のJSON保存・復元、長押しでの重複防止、未知の操作名や混在した設定・自由なコマンドの拒否、確認モードの期限切れと設定の保持、通常レポートとvendor追加ボタンの統合も含めます。v0.3.3の「保存した操作を試す」は有効・保存済みの選択ボタンだけを実行します。入力確認中、未保存、未割り当てでは実行しません。試行は入力回数・保存設定を変更しません。APIにも同じHost/Origin制限を適用し、任意の操作名やキーを受け取りません。

v0.3.4の追加テストは全16修飾キーの組み合わせ、物理キーの保持、⌘Tabの押下・解放、切断・キャンセル・期限による一度だけの解放、古い期限で新しい押下を解除しないことを検証します。これらのテストはOSへキーを送信しません。

macOSのウインドウ操作と通常のショートカットについては [Appleユーザガイド](https://support.apple.com/ja-jp/guide/mac-help/mh35798/mac) を参照できます。

## Bluetooth実機の入力形式（v0.3.1）

056e:013eの実機descriptorは、標準Report 2を5ボタン＋3bit paddingとして宣言していました。Fn1/2/3は標準Report 2ではなく、vendor Report 0x10で受信します。17byte（ID込み）または16byte payloadのうち、payload先頭が12 12の場合だけ、次のbyteのbit5/6/7を追加ボタンとして読みます。実物のFn1=20、Fn2=40、Fn3=80と各解放=00を確認しました。残りのデータは解釈・記録しません。標準Report 2は下位5bit、vendor入力は上位3bitだけを更新し、相互に押下状態を消さないように統合します。他のPIDやvendorレポート、未知のヘッダーや長さには適用しません。追加ボタンのためのHID書込み、descriptor変更、OS設定変更は不要でした。

Fn1/2/3の位置は [ELECOM公式マニュアル](https://www.elecom.co.jp/support/manual_web/products/type_01/m-xgx50mbsk/) の⑥/⑦/⑧で確認できます。側面の前側、中央の大きいボタン、その右下の小ボタンです。
